# assets-src: AgentCraft art pipeline

Deterministic generators for every AgentCraft texture, skin, model and GUI sprite, plus Blender
verification renders. Style: "Warm Studio" (docs/visual-bar.md). This README is generated by
`gen/readme.py`; the manifest below is read from the real `out/` tree.

## Regenerate

```powershell
# one-time: project venv (no global installs)
py -3.9 -m venv assets-src\.venv
assets-src\.venv\Scripts\python -m pip install -r assets-src\requirements.txt

assets-src\.venv\Scripts\python assets-src\build.py            # all shipped assets, ~5 s, no Blender
assets-src\.venv\Scripts\python assets-src\build.py --verify   # rebuild in 2 fresh processes (PYTHONHASHSEED 1, 987654), assert byte-identical
assets-src\.venv\Scripts\python assets-src\build.py --sheets   # + Blender 5.2 renders and review sheets
```

`requirements.txt` pins Pillow (11.3.0): PNG bytes depend on the Pillow/zlib build, and `sync.py --check` compares bytes.

Single steps: `python gen/skins.py [id]`, `gen/blocks.py`, `gen/models.py`, `gen/gui.py`, `gen/ui_style.py`,
`gen/cast_check.py`, `gen/sheets.py [portraits|skins|blocks|gui|all]`, `gen/preview.py <id>` (quick WIP turnaround),
`gen/preview.py --heads <id...|all>` (8-angle head close-ups under exact vanilla entity shading, next to the 8x
face and the portrait at GUI scales: the review view for faces and hair), `gen/preview.py --compare out.png
name=path[:slim] ...` (the same for scratch prototypes, for A/B tests). Blender is called headless
(`blender -b --factory-startup -P blender/render_*.py -- jobs.json`, Cycles/OptiX, Standard view transform).
Block renders use lighting calibrated to vanilla face shading (up 1.0, north/south 0.8, east/west 0.6; emissive
faces at 1.0 x texture; see `blender/studio.py: mc_block_lights`). Skins under `lighting: mc_entity` use an
emission shader that reproduces the game's entity shader exactly: `min(1, 0.4 + 0.6 * (N.L0 + N.L1))` with
vanilla's two light directions, applied to the raw sRGB texel (`blender/mcplayer.py`; a uniform grey skin renders
at 1.00 / 0.74 / 0.50 on top / front / side, matching the formula), so the cast sheet's lineup predicts the game.

Review sheets compare against vanilla textures and use the vanilla font, extracted from the Minecraft client jar
that Fabric Loom caches when the mod is built (nothing is downloaded): `gen/extract_ref.py` (called automatically
by `gen/sheets.py` / `gen/gui_sheet.py`) writes `artifacts/art/_ref/` (reference only, never shipped; gitignored)
and re-extracts when the jar changes. On a clean checkout, build the mod once first
(`$env:GRADLE_USER_HOME='<repo>\.gradle-home'; cd mod; .\gradlew build`) or set `AGENTCRAFT_MC_JAR`.

## In-game check

```powershell
assets-src\.venv\Scripts\python assets-src\ingame_check.py   # ~2-3 min, muted, never takes focus
```

Runs the real 26.3 client from a temp copy of `mod/` (OS temp dir; `mod/` itself is never touched) with a test
resource pack: our namespace plus vanilla stand-in blocks whose blockstates apply our models for chosen property
combinations (connected monitors, glint, every lamp state, podium open/closed, ...), our kit buttons in place of
vanilla's, and the six skins on vanilla mannequins (`profile.texture`). Shots go to `artifacts/art/ingame/`
through the mod's DevBridge (port 7893); the client log is scanned for model/texture/sprite errors
(`artifacts/art/ingame/report.json`). It refuses to start while another Minecraft client is running.

## Sync into the mod

```powershell
python assets-src\sync.py --dry-run   # what would change
python assets-src\sync.py             # copy out\assets -> mod\src\main\resources\assets
python assets-src\sync.py --check     # exit 1 if the mod copy is stale (use before a build)
```

`sync.py` is stdlib-only. It never deletes files it did not put there (ledger:
`mod/src/main/resources/assets/agentcraft/.art-sync.json`), so mod-owned files such as `icon.png` are safe.

**Lang files are merged, not copied.** Minecraft loads one `lang/<locale>.json` per namespace per pack, so the
mod's own keys (keybinds, screen titles, messages) and the generated block/item names share
`assets/agentcraft/lang/en_us.json`. Edit that file in `mod/` as usual: sync owns only the keys it generates
(`block.agentcraft.*`, `item.agentcraft.*`, `itemGroup.agentcraft`), updates them in place, removes ones
assets-src stopped generating, and keeps every other key verbatim in the file's order (a mod value for a
generated key is overwritten with a warning). `--check` compares the merged result by content, so mod-added keys
or CRLF line endings never count as stale.

## Palette

`palette.json` holds every colour value the shipping generators use (named colours, material ramps, status,
cast, skin, hair, per-character details, UI). Generators reference entries by name (`pc("ramps.brass[2]")`,
`P("details.kit.eye")`); `gen/validate.py` fails the build if a quoted hex literal appears in any shipping
generator and checks that every cast colour and accent is a palette entry. Generators may still blend two palette
entries (`mix`) for glints and falloffs, so not every shipped pixel colour is listed: the build prints the split
(currently about 4 in 5 distinct shipped colours are exact palette entries, the rest are such blends).

## Cast

Identity colours live in the blue-violet-magenta arc (205-330 deg hue), which the status palette leaves empty: status uses brass/gold (thinking), teal (working), clay (waiting), red (error), sage (done) and warm grey (idle). Every identity colour is >= 25 CIEDE2000 from every status colour and >= 18 from every other agent (measured by gen/cast_check.py, see `checks`), and the set alternates value (indigo dark, ice light, cobalt mid, violet mid, mulberry dark, rose light) so pairs also separate by lightness for colour-blind viewers; silhouettes (hair/hat/outfit) differ for every agent, so colour is never the only cue. Accents are neutral trims (cream, silver, ink, walnut), each >= 20 CIEDE2000 from every status colour, so nothing tinted with an accent can read as a state. Use `color` for large masses (garments, desk accents), `text_on_dark` for names on any dark surface (nameplates, tooltips, HUD) and `text_on_light` for names on paper GUI and on lit monitor / console screens (warm e-ink paper); both are derived so that the worst case over every surface they are used on (listed in `checks`) is >= 4.5:1 (and text_on_dark >= 5.5:1 on plain ink); the measured worst case per agent is in `contrast`.

Measured: min CIEDE2000 identity-vs-status **25.2**, min agent-vs-agent **18.2**.

## Block contract (what the Java side must declare)

`facing` = direction the front faces = towards the placing player (`ctx.getHorizontalPlayerFacing().getOpposite()`),
like vanilla lecterns/furnaces. Emissive parts follow vanilla `cross_emissive`: an exact duplicate element with
`"light_emission": 15` and `"shade_direction_override": "up"` (26.3 no longer parses the old `"shade": false`),
and every model with one sets `"ambientocclusion": false`. **Render layers are automatic in 26.3**: each quad
goes to SOLID / CUTOUT / TRANSLUCENT from the alpha of the texture region it samples
(`ChunkSectionLayer.byTransparency`), so no `BlockRenderLayerMap` call is needed; the column below says where
the quads end up. Non-cube shapes still need `noOcclusion()`. Suggested luminance is for the block's light level
(separate from the full-bright faces).

## GUI kit

Sprites live in the vanilla GUI sprite atlas: `assets/agentcraft/textures/gui/sprites/kit/<name>.png`. Draw them
with the Minecraft 26.3 (Mojang-named) API:

```java
// graphics: net.minecraft.client.gui.GuiGraphicsExtractor
graphics.blitSprite(RenderPipelines.GUI_TEXTURED,
        Identifier.fromNamespaceAndPath("agentcraft", "kit/panel_paper"), x, y, w, h);
```

36 of the 78 sprites are stretchable and ship a `.png.mcmeta` with `gui.scaling` nine_slice insets, so
vanilla nine-slices them; the other 42 (icons, dots, ring frames, grip, bubble tail, checkboxes) are
fixed-size and drawn at their own size. 1 texel = 1 GUI px. Full manifest with content padding and text colours:
`assets/agentcraft/gui/kit.json`. Colour/typography rules: `ui-style.md`.
